第二單元 規則工程
模組 02 · 規則制定

從 Prompt 提問到 Agentic 交辦：
企業落地的思維質變

傳統 Vibe Coding 只管「把這一個網頁湊出來」；而專業架構師思考的是：如何建立一套規則，讓 AI 能依循同一套標準，源源不絕擴充新功能？

👉 請按鍵盤 →、空白鍵 或點擊下方按鈕開始翻頁
01
現實困境

✦ 你的 AI 員工，每天都是第一天上班

每當你開啟一個新的 Session 或更換視窗，AI 都處於完全失憶狀態：

😵

無規則檔的災難循環

• 每次都要重新貼 500 字的格式要求。
• 常常忘記色彩變數，自己發明新顏色。
• 標點符號半形全形混雜，目錄結構被弄亂。
• 網頁風格前後不一致，宛如補丁拼裝車。

✨

導入 AGENTS.md 的工作流

• AI 每次開工前，系統自動讀取規則檔。
• 清楚知道色票、字體、版面類別與檔案命名。
• 主動遵循防禦規範，不動核心基礎架構。
• 新人進來也能接手，程式碼品質始終如一。

在企業專案中：制度化勝過口頭叮嚀。
02
解決方案

✦ 寫一本專屬的「員工手冊」

將專案規範具體化為專案根目錄的 Markdown 檔案：

A

AGENTS.md

通用 AI Agent 開發規約。適用於 OpenAI Codex、Antigravity、Cursor、Devin 等遵循通用規範的代理系統。

C

CLAUDE.md

專為 Anthropic Claude Code 打造的手冊。在專案根目錄或透過鏈結雙向映射，確保所有 AI 閱讀同一套知識標準。

💡 核心價值

手冊不是寫給人類看的裝飾品，它是約束與引導 AI 決策路徑的最高憲法。

03
手冊結構

✦ 一本優秀手冊的四大支柱

1

這裡是什麼

專案使命、目標使用者、架構核心哲學與業務定位。

2

我的習慣

色票變數、檔案命名、目錄擺放與語意標籤規範。

3

不能做的事

紅線禁區：禁擅自刪檔、禁破壞跳轉、全形標點限制。

4

做完要驗收

單元測試、自動檢核命令、零死鏈驗收標準。

只要這四件事寫得清清楚楚，任何 AI 接手都不會走鐘！
04
協商實作

✦ 規則不要硬擠，跟 AI 討論出來

透過 Socratic 蘇格拉底式單題訪談，讓 AI 幫你萃取出精確規則：

1

請 AI 深度訪談

「請一題一題問我關於網站的風格、受眾、命名習慣與驗收方式。」

2

AI 擬草稿，你裁決

AI 依據回答起草 AGENTS.md，你刪改邊界與補強商務情境。

3

每次收工更新手冊

「這次你踩到了什麼坑？總結教訓寫進手冊，下次絕不再犯。」

規則手冊是一份活的文件，隨著專案迭代會越來越精準厚實！
05
可延伸性

✦ 如何證明規則具有「可延伸性」？

在評分規準中，9~10 分最關鍵的指標是「這套設定具有重複使用與延伸的可能性」：

Tool

標準化命令生成新頁面

在 BizAI Hub 中，AI 只需執行：
python tools/new_content.py lesson --id ai-governance
即可自動依照模板生出符合所有色票、標籤與鍵盤控制的標準簡報！

CI

一鍵自動化健全檢查

修改或新增後，執行：
python tools/validate_site.py
自動檢查全站超連結、CSS 變數完整度與元數據合規性，實現企業級 CI/CD 品質門檻。
