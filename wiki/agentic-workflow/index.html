代理式工作流 (Agentic Workflow)

代理式工作流（Agentic Workflow）指大型語言模型不再僅被動接收單次提示並輸出靜態文本，而是以「自主代理人（Autonomous Agent）」姿態，在封閉或半自主循環中持續進行「規劃（Plan）→ 執行（Act）→ 觀察（Observe）→ 反思修正（Reflect）」的多步驟閉環運作。

✦ 概念定義與本質拆解

在傳統大型語言模型應用中，使用者與模型的互動是「單次推進（Single-Pass）」：提一個問題，獲取一次回答。一旦答案存在邏輯破綻或資料缺失，模型無法自主補救。

代理式工作流將模型嵌入一個具備狀態機（State Machine）的運行環境（Harness）。其核心特徵包含四大機制：

  • 動態任務拆解（Decomposition & Planning）：將一個龐雜的高階指令（如「分析這份 100 頁的企業永續報告書」）拆解為循序漸進的微型子任務。
  • 工具調用閉環（Tool Execution Loop）：AI 根據需要主動決定讀取哪份檔案、查詢哪個 API，並接收環境回傳的真實輸出。
  • 狀態記憶持久化（State Persistence）：跨多輪步驟保存中繼變數與推論歷程，即使某個步驟失敗也能回滾或重試。
  • 自我反思與批判（Self-Reflection）：在提交最終成品前，扮演審稿者角色對自身產出進行質量檢驗。

✦ 企業商管應用情境

🏢 企管落地實例：供應鏈庫存異常預警與採購決策特工

多部門資料串接與跨系統自動決策

某跨國製造企業過往需配置 3 名專員，每日手動比對 ERP 庫存水位、即時航運 API 與天氣警報。導入代理式工作流後：

1. 每日自動觸發：Agent 於凌晨 04:00 自動讀取供應商進度與海外船期。
2. 偵測到紅海航道延誤：自動調用本地 SQL 查詢關鍵物料安全天數，發現 14 天後將斷料。
3. 執行避險試算：自動比對備用供應商報價與航空運費，生成採購決策簡報。
4. 提交核准：於上班時將完整的決策建議與公文草稿推播給採購總監，總監僅需一鍵核准即可完成採購簽核。

✦ 方案對比與決策矩陣

商管決策者在評估自動化技術時，常將傳統 RPA（機器人流程自動化）與 Agentic Workflow 混淆，其核心維度差異如下：

指標維度 傳統 RPA / 寫死腳本 對話式 LLM (Chat) 代理式工作流 (Agentic Workflow)
面對非預期異常 直接當機報錯 需人類重新下 Prompt 自主診斷錯誤、調整策略並自動重試
非結構化資料理解 極弱（僅能處理固定表格） 極強，但無法觸發後續系統 強大語意解析，並能調用工具落地操作
維護成本與適應彈性 介面一改整組重寫 每次從零開始 仰賴 AGENTS.md 集中配置，彈性極高
